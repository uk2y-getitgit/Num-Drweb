# /weekly — 주간 점검 (오케스트레이터)

## 이 스킬의 자리

release / issue-key / qa / promo 는 각각 "어떻게 하는가" 다.
이 스킬은 **"지금 무엇을 해야 하는가"** 를 정하고 그 넷에게 넘긴다.

주 5~15시간 조건에서 이 점검은 **30분**이다. 길어지면 실행 시간을 잡아먹는다.

## Phase 0 — 컨텍스트 확인

```bash
ls 운영기록/주간/ 2>/dev/null | tail -3     # 지난 점검 기록
```

| 상황 | 모드 |
|---|---|
| 기록 없음 | **초기** — 전체 상태를 처음부터 수집 |
| 지난 기록 있음 | **후속** — 지난주 목표 달성 여부부터 확인하고 차이만 본다 |
| 특정 영역만 요청 | **부분** — 해당 Phase 만 실행 |

## Phase 1 — 상태 수집 (읽기만, 5분)

```bash
git log --oneline -10                              # 이번 주 무엇을 했나
git status --short                                 # 커밋 안 된 작업
grep '"version"' package.json                      # 앱 버전
grep -n "DOWNLOAD_URL" web/purchase.html           # 홈페이지가 가리키는 설치파일
grep -c "\[ \]" 사업화_실행계획.md                  # 남은 미결 항목 수
```

**세 값 일치 확인** — `package.json` 버전 / R2 파일명 버전 / 홈페이지 표기 버전.
어긋나 있으면 그 주의 1순위는 무조건 `/release` 다.

사람에게 물어서 채우는 값 (저장소에서 알 수 없다):
- 이번 주 들어온 문의 건수 / 미답변 건수
- 입금·발급 대기 건수
- 다음 주 사무실 출근일 (S1 라이선스 검증은 두 번째 PC 가 있어야 한다)

## Phase 2 — 우선순위 판단

아래 순서로 자른다. 위쪽이 아래쪽보다 항상 먼저다.

| 순위 | 조건 | 넘길 곳 |
|---|---|---|
| 1 | 미답변 문의가 있다 | `/issue-key` — 신뢰는 응답 속도에서 깎인다 |
| 2 | 발급·입금 대기가 있다 | `/issue-key` |
| 3 | 세 값이 어긋나 있다 | `/release` |
| 4 | S1 라이선스 검증 미완 + 출근일 확정 | `/qa` (Phase 3 라이선스 5종) |
| 5 | 홈페이지에 사실과 다른 문구가 남아 있다 | `/promo` |
| 6 | 위가 다 없다 | 계획서 S 단계의 다음 미결 항목 1개 |

**주 5시간밖에 못 쓰는 주에는 1·2번만 지킨다.** 홍보와 제품 개선은 미뤄도 되지만,
문의 대응이 밀리면 그때부터 신뢰가 깎인다.

## Phase 3 — 실행 위임

선택한 작업을 해당 스킬로 넘긴다. **한 주에 착수하는 큰 항목은 하나**로 제한한다.

| 작업 | 호출 |
|---|---|
| 배포 | `/release` → `release-pilot` |
| 발급·문의 | `/issue-key` → `license-desk` |
| 점검·검증 | `/qa` → `qa-runner` |
| 문구·홍보 | `/promo` → `market-writer` |

여러 개가 동시에 필요하면 **순서대로** 진행한다. 배포 전에는 반드시 `/qa` 가 앞선다.

## Phase 4 — 기록

`운영기록/주간/YYYY-MM-DD.md` 에 남긴다. 형식:

```markdown
# 주간 점검 YYYY-MM-DD

## 지난주 목표 달성
- [x] <항목> — 근거
- [ ] <항목> — 막힌 이유

## 현재 상태
- 앱 버전 / R2 / 홈페이지 표기: 1.2.4 / 1.2.4 / 1.2.4  ✅
- 미결 항목: n건 (S0 n / S1 n / …)
- 문의: 접수 n / 미답변 n
- 거래: 발급 n / 대기 n

## 이번 주 목표 (최대 3개)
1. <가장 앞선 순위 1개>
2. …

## 넘긴 작업
- /release → 진행 중 / 완료
```

`사업화_실행계획.md` 의 완료 항목도 이때 체크한다. **근거 한 줄 없는 체크는 하지 않는다.**

## 에러 핸들링

| 상황 | 대응 |
|---|---|
| 사용자가 문의·거래 수치를 모름 | "미확인" 으로 기록하고 진행. 추정치를 쓰지 않는다 |
| 넘긴 스킬이 승인 대기로 멈춤 | 주간 기록에 "승인 대기" 로 남기고 다음 항목으로 넘어가지 않는다 |
| 지난주 목표가 3주 연속 미달 | 목표가 과하거나 막힌 것이다. 항목을 쪼개도록 제안한다 |

## 테스트 시나리오

- **정상**: "주간 점검" → 상태 수집 → 세 값 일치 확인 → 우선순위 1개 선정 → 기록
- **후속**: "지난주 이어서" → 지난 기록 읽기 → 미달 항목 먼저 → 차이만 보고
- **에러**: 세 값 불일치 발견 → 다른 항목 제쳐두고 `/release` 를 그 주 1순위로 배치

## 금칙

- 이 스킬에서 직접 배포·발급·게시하지 않는다. 판단하고 넘기는 것이 역할이다.
- 확인하지 못한 수치를 추정해서 적지 않는다.
- 한 주에 큰 항목을 둘 이상 착수하지 않는다.
