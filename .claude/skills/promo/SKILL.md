# /promo — 홈페이지·홍보 콘텐츠

## 이 스킬이 지키는 것

이 제품 홍보의 가장 큰 위험은 과장이 아니라 **어긋남**이다. 홈페이지는 v1.2.4 화면을
보여주는데 설치파일은 v1.2.3 이었고, 유료 혜택으로 적어둔 안드로이드 앱과 집계표 엑셀은
받는 경로가 없었다. 둘 다 거짓말할 의도 없이 생긴 어긋남이고, 판매를 열면 그대로
표시광고 문제가 된다.

**규칙: 홈페이지의 모든 기능 주장에 대해 "그 기능이 있는 코드 위치" 를 댈 수 있어야 한다.**
못 대면 그 문장은 쓰지 않는다.

## Phase 0 — 사실 확인 먼저

문구를 쓰기 전에 근거를 잡는다. **문서(`CLAUDE.md`)보다 코드가 우선**이다 —
문서가 실제보다 앞서 적혀 있는 사례가 이미 있었다.

```bash
grep -rn "<기능 키워드>" js/ index.html     # 기능이 실제로 있나
grep -rn "1\.2\.[0-9]" web/                 # 버전 표기 분포
grep -rn "<고칠 문구>" web/                 # 영향 받는 페이지 전부
```

한 페이지만 고치면 페이지 간에 말이 어긋난다. **`web/` 5개 파일을 항상 함께 확인한다.**

| 파일 | 성격 |
|---|---|
| `web/index.html` | 메인 랜딩 |
| `web/product.html` | 제품 소개 |
| `web/purchase.html` | 가격·구매 절차·다운로드 |
| `web/guide.html` | 사용 가이드·단축키·FAQ |
| `web/terms.html` | 약관·개인정보·환불 — **법적 문구, 사람 승인 필수** |

## Phase 1 — 작업 유형 분기

| 요청 | 절차 |
|---|---|
| 기능·가격 변경 반영 | A. 홈페이지 동기화 |
| 카페·단톡 게시글 | B. 커뮤니티 |
| 블로그·검색 유입 | C. SEO 글 |
| 업체 영업 | D. 제안 메일 |

## A. 홈페이지 동기화

1. Phase 0 으로 영향 범위 전부 찾기
2. 수정안 제시 → **[승인]** → 반영
3. 가격·법적 문구·사업자 정보는 **반드시 승인 후**. 자리표시자(신고번호·주소)를
   임의 값으로 채우지 않는다
4. `홍보_카피_모음.md` 갱신

## B. 카페·단톡방

- 광고 티가 나면 삭제되거나 반감을 산다. **정보 전달이 본문, 도구 소개는 마지막 한 단락**
- 실제 작업 흐름(도면 → 넘버링 → 사진 매칭 → 사진첩 PDF)을 경험처럼 서술
- 게시 전 해당 카페의 홍보 규정을 사람이 확인하도록 안내를 붙인다

## C. 블로그·SEO

- 검색어 후보: `외관조사망도 넘버링` / `안전점검 결과보고서 사진첩` /
  `외관조사망도 프로그램` / `시설물 점검 사진 정리` / `점검 사진 파일명 자동 변경`
- **한 편에 검색어 하나.** 제목·첫 문단·소제목에 자연스럽게
- 구성: 문제 → 기존 방식의 수고 → 해결 흐름 → 실제 화면 → 체험판 안내
- 월 1~2편 누적 전제, 이전 글과 내부 링크

## D. 업체 직접영업

- 제안 메일은 **스크롤 한 번 안에** 끝낸다. 상세는 첨부 1장 요약으로
- 첫 문장은 상대의 업무 언어로 — "외관조사망도 번호 매기고 사진 정리하는 그 작업"
- 실측하지 않은 수치를 쓰지 않는다. 대신 작업 단계 수로 말한다
  ("클릭 두 번이면 지시선과 번호가 끝납니다")
- 체험판 링크 필수, 첫 메일에 구매 요구는 넣지 않는다

## 지금 반드시 고쳐야 할 문구 (미해결)

- `web/purchase.html` 유료 플랜 공통 혜택
  - **외관조사 집계표 엑셀 양식 — 실물이 없다.** 만들기 전까지 혜택에서 내리거나 "준비 중" 표기
  - **안드로이드 앱 — 실물(APK)은 있으나 전달 경로가 없다.** "구매 후 메일로 전달" 처럼 실제 방법 명시
- **요금제** — 구독 2종(월·연간)은 자동결제 인프라가 없어 수동 청구다.
  체험판 / 일회성 / 평생 3종으로 단순화하기로 확정

## 테스트 시나리오

- **정상**: "사진첩 기능 카페에 소개하는 글 써줘" → 코드에서 기능 확인 → 정보전달형 본문 + 마지막 단락 소개
- **부분**: "가격 바뀌었어" → 5페이지 전부 grep → 수정안 → 승인 → 반영 → 카피 갱신
- **에러**: 근거 못 찾음 → 그 문장 쓰지 않고 "이 기능이 실제로 있습니까" 확인 요청

## 금칙

- 코드에서 확인되지 않은 기능을 쓰지 않는다
- 실측하지 않은 수치("90% 단축")를 쓰지 않는다
- 경쟁 제품·기존 엑셀 매크로를 비방하지 않는다 — 차이만 말한다
- 사업자 정보·신고번호·환불 조건을 임의로 채우지 않는다
- 게시·발송을 대신하지 않는다 — 초안까지가 범위
