# /qa — 품질·회귀 점검

## 이 스킬이 지키는 것

**돌리지 않은 것을 통과로 적지 않는다.** 보고는 항상 `통과 n / 실패 n / 확인 못 함 n` 으로 끝난다.
"환경 문제로 보임" 은 통과가 아니라 **확인 못 함**이다.

검사 수단이 비대칭이라는 점을 전제로 움직인다.

| 영역 | 수단 |
|---|---|
| 활성화 서버 | `cd server && npm test` — 좌석 경쟁·반납·증서 검증·CSRF |
| 앱 | **자동 검사 없음.** 회귀 스크립트를 만드는 것이 이 스킬의 미결 과제 |

## Phase 0 — 범위 결정

```bash
git diff --stat            # 무엇이 바뀌었나
git log --oneline -5
```

| 변경 범위 | 돌릴 것 |
|---|---|
| `server/` | 서버 테스트 + 라이선스 항목 |
| `js/`·`index.html`·`css/` | 앱 체크리스트 (해당 기능 중심) |
| `web/` | 링크·버전 표기 점검만 |
| 배포 직전 | 전체 |

건너뛴 항목은 **건너뛴 사실을 보고에 적는다.** 지난 점검에서 실패한 항목이 있으면 먼저 재확인한다.

## Phase 1 — 자동 검사

```bash
cd server && npm test
```

통과 수와 실패 시나리오 이름을 그대로 인용한다. **테스트를 고쳐서 통과시키지 않는다.**

앱 회귀 스크립트가 생기면 여기서 함께 실행한다 (§미결 과제).

## Phase 2 — 수동 체크리스트

사람이 화면을 봐야 아는 항목은 목록으로 출력하고, 사용자가 알려준 결과만 기록한다.

| # | 항목 | 통과 기준 |
|---|---|---|
| 1 | 도면 불러오기(PDF·이미지 드래그) | A4 변환 + 페이지 카드 생성 |
| 2 | 넘버링 2클릭 | 지시선 + 번호 박스, 접두어 반영 |
| 3 | 사진 폴더 연결 → 자동매칭 | 매칭 항목 녹색 |
| 4 | 사진 파일명 일괄 변경 | 원본 폴더에 반영 |
| 5 | 외관집계표 불러오기 | 건수 표시 + 미매칭 경고 |
| 6 | 사진첩 PDF 저장 | 6칸 배치, 빈 칸 "사진 없음" |
| 7 | 도곽 ON/설정 서랍 | 캔버스 안 가림, 즉시 반영 |
| 8 | 장비시험망도 모드 | 도형 그룹 해제, 계기바 정렬 유지 |
| 9 | 다크/라이트 전환 | 잉크 3색 동일, 재시작 후 유지 |
| 10 | 체험판 저장 게이트 | 여러 장 작업 → PDF 1장 + 워터마크 + 안내 |

## Phase 3 — 라이선스 5종 (S1 게이트 · 두 번째 PC 필요)

**첫 유료 판매 전에 반드시 통과해야 하는 항목.** 돈과 직결되거나 현장에서 앱이 안 열리는 문제다.

| # | 검증 | 통과 기준 |
|---|---|---|
| L1 | 2대 제한 | PC-A·PC-B 활성화 후 3대째 거절, 좌석 2/2 |
| L2 | 좌석 반납 | `/admin/release` 성공 → 같은 기기 재활성화 성공 |
| L3 | 키 정지 | `/admin/revoke` 후 활성화 거절 |
| L4 | 오프라인 재실행 | 네트워크 차단 후 실행 → 정상 실행·저장 |
| L5 | 체험판 저장 게이트 | Phase 2 의 10번과 동일 |

두 번째 PC 가 없으면 **L1~L4 를 "확인 못 함" 으로 남긴다.** 추정으로 통과시키지 않는다.

## Phase 4 — 보고

```
자동   : server 테스트 통과 n / 실패 n
수동   : 통과 n / 실패 n / 확인 못 함 n
실패   : <항목> — 재현 절차 <...>
건너뜀 : <항목> — 사유 <...>
판단   : 배포 가능 / 배포 보류
```

결과는 `사업화_실행계획.md` 의 해당 항목(S1 등)에 체크와 근거 한 줄로 남긴다.

## 미결 과제 (이 스킬이 스스로 해결해야 할 것)

- [ ] `CLAUDE.md` 가 "`test_bounds.mjs` 가 매번 검사한다" 고 적었지만 **그 파일은 없다.** 문서 정정
- [ ] 앱 회귀 스크립트 작성 — 우선순위 3가지
  1. **작업범위 안내선이 출력물에 새지 않는가** — `renderAnnotations` 에만 그려야 하고
     `createPageExport`(PDF·사진첩)에는 없어야 한다. 깨지면 고객 보고서에 점선이 찍힌다
  2. **사진첩 배치 규칙** — 집계표 행 순서, 6칸 고정, 문구 둘째 줄 줄바꿈
     (치수 `(0.2x2.1)` 있으면 치수 앞, 없으면 `(보수완료)` 앞)
  3. **도면 배율 변경 후 넘버링 좌표** — `Annotation.transformCoords` 로 지시점이 같은 위치 유지

## 테스트 시나리오

- **정상**: "배포 전에 점검해줘" → 전체 범위 → 서버 테스트 + 체크리스트 출력 → 세 숫자 보고
- **부분**: "사진첩 쪽만 고쳤어" → `git diff` 로 범위 판별 → 5·6번 + 관련 항목만, 건너뛴 항목 명시
- **에러**: 서버 테스트 실패 → 실패 시나리오 인용, 배포 보류 판단

## 금칙

- 돌리지 않은 항목을 통과로 적지 않는다
- 검사를 통과시키려고 기준을 낮추지 않는다
- 제품 코드를 임의로 고치지 않는다 (원인 위치까지 보고, 수정은 별도 승인)
