# 벤치마킹 — 젠트릭스(Zentrix) / 홈체크

> 조사 2026-08-22. 출처: `zentrix.kr` · `zentrix.kr/docs` · 공식 튜토리얼 영상
> (「시설물 안전법 정기안전점검 ㅣ 보고서 자동화 ㅣ 젠트릭스 어플 튜토리얼」, 11분 17초,
> 채널 "홈체크 젠트릭스", 발표자 이정욱 차장). 영상 자막 87구간 전문을 받아 분석했다.

## 1. 무엇을 하는 회사인가

**홈체크** — 주택 점검 업체이자 안전진단 전문기관. 즉 **자기가 쓰려고 만든 도구를 파는 회사**다.
발표자가 현직 차장이고, 영상 초반이 "디지털 카메라로 찍고 출력한 도면에 손으로 적어서
사무실에서 옮기는" 현행 업무의 불편을 나열하는 것으로 시작한다.

**우리와 출발점이 같다.** 다른 것은 도달한 범위다.

| | 젠트릭스 | Quickspect |
|---|---|---|
| 형태 | 태블릿·폰 앱 + 웹(PC) | Windows 설치형(Electron) |
| 저장 | 클라우드 서버 동기화 | 로컬 파일 |
| 현장 입력 | **태블릿으로 현장에서 직접** | 없음(사무실 PC 작업) |
| 판매 | 기업 상담 · 트라이얼은 전화로 ID 배정 | 무통장입금 · 일회성 구매 |
| 앱 | `kr.homecheck.zentrix` (Play·App Store) | 미출시(퀵스샷 예정) |

## 2. 젠트릭스의 작업 흐름 (영상 기준)

```
로그인(웹/앱 공용 계정) → 과업 생성 → 도면 PDF 업로드
   → 동(棟)·층 구분 지정 → 도면 이름 편집·복사·드래그 정렬
   → [현장] 태블릿으로 결함 입력 (사진은 카메라 직결)
   → [사무실] 웹에서 검수·스타일 정리
   → 출력 (한글/엑셀/JPG/CAD)
```

### 2-1. 결함 입력 — 4가지 표기 방식

**점 · 방향 · 영역 · 그리기**

- **점**: 위치 하나를 찍는다 (우리 "점" 도구와 같다)
- **방향**: 화살표. "점검자가 이쪽 시선으로 바라봤다"를 표현 (우리 "화살표"와 같다)
- **영역**: 범위 지정. 테두리를 투명/실선, 외곽선을 실선/점선/**구름 모양(revision cloud)**,
  채움 여부와 색상까지 선택 (우리 "해치 도형"의 상위 호환)
- **그리기**: 도면 위에 자유 필기·텍스트. 조사위치도에는 안 넣지만 메모가 필요할 때

### 2-2. 결함 하나에 붙는 데이터 — 여기가 결정적 차이다

우리는 번호만 붙인다. 젠트릭스는 **결함마다 속성 레코드**를 만든다.

```
사진 · 구조유형 · 부재 · 구조체 여부 · 결함유형 · 진행 여부
· 폭 / 길이 / 개수 · 발생원인 · 보수현황 · 메모
```

현장에서 터치로 입력해 두면 그대로 **손상결함표**가 된다.
출력된 표의 열 구성은 `넘버 · 위치 · 부재명 · 구조체 유형 · 결함유형 · 손상규모 ·
진행상황 · 누수여부 · 발생원인 · 사진번호`.

### 2-3. 전회차 대조 — 가장 인상적인 기능

- 이전 보고서의 결함을 **보라색**으로 도면에 미리 얹어 놓고 점검을 시작한다
- 현장에서 그 결함을 누르면 **이전 사진이 뜬다** → 같은 위치를 찾아 촬영
- 사진을 찍는 순간 **빨간색(금회차)으로 전환**되고 금회차 항목으로 넘어온다
- 변화가 없으면 **수정 없이 사진만 찍어도** 보고서가 만들어진다

우리 `CLAUDE.md` 가 "(보류) 전차대조 사진첩"으로 미뤄둔 바로 그 기능이다.
젠트릭스는 이것을 **핵심 판매 포인트**로 쓰고 있다.

### 2-4. 출력

| 산출물 | 형식 |
|---|---|
| 시설물 사진첩 · 외관조사 사진첩 · 손상결함표 · 전차 비교 사진 · 결함 사진 · 조사위치도 | **한글(HWP) · 엑셀 · 원본 JPG · CAD** |

출력 옵션이 실무를 정확히 안다.

- **층별 넘버링 방식 선택** — 층마다 1번부터 다시 시작 / 전체 연속 번호
- **번호 진행 방향** — 옥탑→지하 / 지하→옥탑 (발주처·회사마다 다르다)
- **보수완료 항목 포함 / 제외**
- 단위 mm / m 선택
- 도면에 도면 이름 텍스트 얹기(작게·보통·크게) — 발주처 도면에 층 표기가 없을 때

> 영상의 표현으로는 이 출력만으로 정기안전점검 보고서의 **부록 부분이 전부 채워진다**고 한다.
> 본문은 별도의 "문서 작성" 페이지에서 평가항목·점검결과·평가결과를 터치 체크와
> 필기 모드로 입력해 출력한다.

### 2-5. 회사별 맞춤 설정

부재별로 어떤 결함 항목을 띄울지, 그 결함을 어떤 단위로 입력할지를 회사가 정한다.

- 바닥 슬래브 · 균열 → 폭·길이로 입력, 기본 발생원인을 "건조수축균열",
  기본 보수방안을 "표면처리공법"으로 지정
- 벽체 · 망상균열 → **면적**으로 입력. 현장에서 폭·길이를 넣으면 **면적이 자동 계산**
- 회사마다 쓰는 용어를 직접 추가

홈페이지 문구로는 "기존에 점검하던 용어와 방식을 그대로 사용할 수 있습니다".
**도구에 사람을 맞추지 않고, 회사 양식에 도구를 맞춘다.**

### 2-6. 표기 스타일

번호 풍선 모양, 영역 채움, **번호풍선 크기 · 연결선 굵기 · 숫자 크기 · 영역 선 굵기**를
도면 축척에 맞춰 개별 조정. 우리 넘버링 배율 슬라이더(0.5×~3.0×)의 세분화 버전이다.

## 2-7. 화면 직접 확인 (2026-08-22 · 영상 프레임 캡처)

자막만으로는 안 보이는 UI 구조를 영상 6개 시점에서 화면으로 확인했다.

### 화면 레이아웃

```
┌──────────┬──────────────────────────────┬─────────────┐
```

### 결함 정보 탭

- **부재를 버튼 그리드로 고른다** — 바닥슬래브 / 천장슬래브 / 파라펫 / 계단슬래브 /
  지정벽돌 / 계단난간 / 천장마감재 / 드라이비트 / 외부벽체 / 담장 / 캐노피 / 경계석
- 구조체 여부: `비구조체` / `구조체` 2택
- 결함 유형: `균열` / `파손` …
- 진행 여부: `진행 없음` / `진행 중` 2택
- **폭**: `− 0 mm +` 스테퍼 + **구간 빠른입력 버튼**
  `0.1mm미만` `0.1~0.2` `0.2~0.3` `0.3~0.5` `0.5mm이상` `직접입력`
- 길이·개수도 같은 방식 (`500` `1000` `3000` / `5` `10` 프리셋)
- 발생원인도 프리셋 (`건조수축` `이질재 접합` …)

> **손가락으로 빠르게 찍는 것에 최적화돼 있다.** 현장에서 키보드 없이 태블릿으로
> 입력하는 것이 전제라, 자유 입력보다 프리셋 버튼이 먼저다.

### 스타일 탭 — 번호 표기를 통째로 제어

| 항목 | 선택지 |
|---|---|
| 모양 | `구름` `점선` `실선` |
| 영역 채우기 | `투명` `채움` |
| **색상** | **테두리 · 채우기 · 숫자를 각각 따로** (각 7색 팔레트) |
| 번호 풍선 크기 | 슬라이더 |
| 연결선 굵기 | 슬라이더 |
| 숫자 크기 | 슬라이더 |
| 영역 선 굵기 | 슬라이더 |

패널 상단 안내가 중요하다 — "스타일 변경 시 이후 전체 설정을 변경해도 적용되지 않습니다.
전체 설정을 적용하려면 초기화 버튼을 눌러주세요."
**개별 스타일이 전역 설정을 덮어쓰고, [초기화]로 전역에 다시 붙는다.**
우리 `hatchColor` 가 "그리는 시점 값을 도형에 고정"하는 것과 같은 사상이다.

### 결함 선택 시 뜨는 플로팅 메뉴

`[점 ∨] [색상] [복제] [+추가] [삭제]` — 영역이면 `[실선] [채움]` 이 더 붙는다.
**`점 ∨` 드롭다운으로 이미 찍은 표기를 점↔방향↔영역으로 바꾼다.**

### 번호 배치

번호 풍선을 도면 밖까지 끌어낼 수 있고 지시선이 그만큼 늘어난다(37번 사례).
**자동 줄맞춤·정렬 UI는 확인되지 않았다** — 수동 배치로 보인다.
우리의 자동정렬(겹침 방지)에 해당하는 기능은 화면에서 못 봤다.

### 전회차 대조 화면

같은 도면에 **보라색 번호(전회차)** 와 **빨간색 번호(금회차)** 가 공존한다.
좌측 목록도 `🔵전회차 3건 / 🔴금회차 14건` 으로 나뉘고 **번호는 각각 1부터** 매겨진다.

### 출력 모달 — 실무 옵션이 촘촘하다

```
2. 외관조사 / 정밀점검 선택   ○전체  ○외관조사만  ○정밀점검만
3. 층 선택                  ●층마다 1번부터  ○전체 번호가 이어서
   [1 옥탑층][2 지상1층][3 지상2층] … [12 지하1층][13 지하2층][14 지하3층][15 지하4층]
   ↑ 칩 앞의 숫자 = 고른 순서. 고른 순서대로 결함 순번이 매겨진다
   [전체 선택] [선택 초기화]
4. 출력 옵션   이전회차 보수완료 항목  ●포함하지 않음 ○포함
              단위  폭 ●mm ○m   길이 ●mm ○m
```

**층 칩을 클릭한 순서가 곧 번호 순서**라는 UX가 영리하다.
옥탑→지하든 지하→옥탑이든 라디오 버튼이 아니라 "고른 순서"로 해결한다.

우측에는 **출력 이력**이 남는다 — `손상결함표 / 완료 / 2026.01.07 17:55 / ⬇ 🗑`.
한글본과 엑셀본이 아이콘으로 구분되고 재다운로드된다.

### 실제 손상결함표 출력물

머리말 `건양대학교병원 | 제2장 현장조사 | <계 속>`, 층마다 `■ 지하1층` 섹션.

| NO | 위치 | 부재명 | 구조체 유형 | 결함의 유형 및 형상 | 폭(mm) | 길이(mm) | 면적(㎡) | 개소(EA) | 진행상황 | 누수여부 | 발생원인 추정 | 사진번호 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| 93 | 지하1층 | 벽체 | 비구조체 | 수직균열 | 0.2 | 2000 | 0.0004 | 2 | O | X | 2 | 92 |
| 96 | 지하1층 | 상부슬래브 | 비구조체 | 누수흔적 | 0 | 0 | 0.5 | 1 | O | O | 3 | — |

세 가지가 눈에 띈다.

1. **`NO` 와 `사진번호` 가 서로 다른 열이다** (93 ↔ 92). 결함 순번과 사진 순번이 독립적으로
   관리된다 — 우리 "사진 자동매칭"이 풀려는 문제와 정확히 같다
2. **면적이 자동 계산된다** (0.2mm × 2000mm = 0.0004㎡)
3. 발생원인이 **숫자(2, 3)** — 범례 번호로 코드화해서 표 폭을 아낀다

## 3. 우리와의 격차

### 🔴 우리에게 없는 것

| # | 기능 | 무게 |
|---|---|---|
| G1 | **결함 속성 데이터** (구조유형·부재·결함유형·규모·원인·보수) | 이게 없으면 손상결함표를 못 만든다. **가장 큰 격차** |
| G2 | **손상결함표 출력** (한글/엑셀) | 우리는 사진첩 PDF 하나뿐 |
| G3 | **전회차 대조** | 보류 상태. 경쟁사는 핵심 기능 |
| G4 | **현장 입력** (태블릿) | 우리는 사무실 PC 전용. 퀵스샷이 사진에만 관여 |
| G5 | **회사별 용어·입력 방식 설정** | 우리는 접두어·색상 정도 |
| G6 | CAD 출력 | 발주처 제출용으로 요구되는 곳이 있다 |
| G7 | 클라우드 동기화·공유 링크 | 팀 작업 시 필요 |

### 🟢 우리가 나은 것

| # | 강점 | 왜 의미가 있나 |
|---|---|---|
| A1 | **서버가 필요 없다** | 인터넷 없는 지하·기계실에서도 그냥 돈다. 젠트릭스도 오프라인 모드가 있지만 결국 계정·서버 전제다 |
| A2 | **일회성 구매** | 젠트릭스는 "기업 고객 상담"·전화 ID 배정. **1인·소규모 업체가 카드 긁듯 살 수 있는 물건이 아니다** |
| A3 | **기존 엑셀 집계표를 그대로 받는다** | 이미 쓰던 외관집계표를 불러와 3자 대조. 업무 방식을 안 바꿔도 된다 |
| A4 | **2클릭 넘버링** | 도면 넘버링 속도 자체는 우리가 더 가볍다 |
| A5 | 도곽·장비시험망도 | 젠트릭스 자료에서 확인되지 않았다 |

### ⚪ 흥미로운 사실

젠트릭스 `/docs` 는 **AI 자동 보고서를 "2026년 예정"(현재 미구현)** 으로 적고 있다.
홈페이지 히어로는 "회사에 맞춤형 자료를 AI가 작성해드립니다"라고 단언한다.
**경쟁사도 아직 다 만들지 못했다** — 우리가 늦은 게 아니다.

## 4. 시사점

### 4-1. 정면으로 붙지 않는다

젠트릭스는 **점검 업무 전체를 대체하는 플랫폼**이고, 우리는 **도면 넘버링과 사진첩을
빠르게 끝내는 도구**다. 같은 제품이 아니다.

- 젠트릭스를 사려면 **회사가 일하는 방식을 그 시스템에 옮겨야 한다** (과업 생성, 계정, 서버)
- 우리는 **설치만 하면 오늘 쓰던 방식 그대로** 도면과 엑셀을 넣고 결과물을 뽑는다

**"플랫폼으로 갈아탈 준비가 안 된 사람"이 우리 시장이다.** 1인 사업자, 소규모 업체,
연 몇 건만 하는 곳, 회사 방침상 클라우드를 못 쓰는 곳.

### 4-2. 그래도 배워야 할 세 가지

| 우선 | 항목 | 이유 |
|---|---|---|
| **1** | **결함 속성 입력 + 손상결함표 출력** (G1·G2) | 넘버링과 사진첩만으로는 보고서의 절반이다. 속성을 담기 시작하면 표가 따라 나온다. 다만 이건 제품의 성격을 바꾸는 큰 변경이라 별도 판단이 필요하다 |
| **2** | **전회차 대조** (G3) | 이미 계획에 있고(보류), 경쟁사가 핵심으로 쓴다. "이전 결함을 도면에 미리 얹고, 사진만 찍으면 금회차로 넘어온다"는 흐름은 우리 구조로도 만들 수 있다 |
| **3** | **출력 옵션의 실무 감각** (2-4) | 층별 1번부터/연속 번호, 옥탑→지하/지하→옥탑, 보수완료 포함/제외. **코드는 작고 실무 체감은 크다.** 지금 당장 넣을 수 있는 것들이다 |

### 4-3. 홍보에 쓸 수 있는 대비

젠트릭스가 "우리 시스템으로 오세요"라면, 우리는 **"쓰던 대로 하세요, 시간만 줄이세요"** 다.
`web/` 문구를 이 축으로 다듬을 여지가 있다 — 다만 **경쟁사를 깎아내리는 방식은 쓰지 않는다.**

## 5. 확인하지 못한 것

- **가격.** 홈페이지에 "프로모션 기간 무료"만 있고 요금표가 JS 렌더링이라 못 읽었다.
  기업 상담 폼(`forms.gle/...`)과 전화(1522-5401)로만 안내된다
- 실제 출력물(한글·엑셀 파일)의 서식 품질
- 앱 사용성 — 앱을 설치해 보지 않았다
- 고객 후기는 사이트에 **같은 내용 하나가 반복** 게시되어 있어 표본이 없다
