## 1. 지금 UI의 문제 (개선 근거)

| # | 증상 | 원인 |
|---|------|------|
| 1 | "AI가 만든 화면" 같다 | 인디고 `#5B5BD6` + Inter + 6px 라운드 + 옅은 회색 보더는 SaaS 템플릿의 기본값이다. 시설물 점검 도구라는 정체성이 화면 어디에도 없다 |

| 5 | 슬라이더가 항상 보인다 | 선두께·넘버링·범례·도면 배율 슬라이더 4개가 상시 노출. 세션당 몇 번 안 만지는 값이 제일 자주 쓰는 도구와 같은 자리를 차지한다 |

## 2. 방향 — 제도 콘솔

**SaaS 대시보드가 아니라 제도 기기의 조작반으로 만든다.**

- **크롬(기기 몸체)은 흑연, 도면만 흰 종이.** 화면에서 유일하게 밝은 면이 도면이 되므로 시선이 자동으로 작업 대상에 간다. AutoCAD·Photoshop 계열의 정통 문법이기도 하다.
- **칸(bay) = 도곽 셀 문법.** 이 앱이 이미 그리고 있는 도곽의 `PROJECT TITLE │ 내용` 구조를 UI 구조로 그대로 가져왔다. 버튼은 낱개로 두지 않고 반드시 `라벨 │ 버튼들` 칸에 담는다. 이것이 요청하신 **버튼 식별(칸)** 의 답이다.
- **색은 의미에만.** 잉크 3색(결함·보수·신규)은 도면에 실제로 찍히는 색이므로 UI에서도 그 뜻으로만 쓰고, 앱 자신의 상태는 계기 램프색(amber) 하나로 말한다.

### 램프 규칙 (하나만 외우면 되는 규칙)

> **선택된 버튼은 아래 2px 램프가 켜진다. 램프색은 그 도구의 색이다.**
> 색이 없는 도구(화살표·직선·모드)는 amber, 색을 가진 도구(결함·보수·신규)는 자기 잉크색.

색맹 사용자도 "아래 줄이 켜졌다"는 형태로 선택 여부를 읽을 수 있다.

### 주요 버튼은 강조색을 쓰지 않는다

`열기`, `폴더 선택`, `적용` 같은 주요 동작은 **종이색 키**(밝은 흰 버튼)다.
amber 는 "지금 선택된 것" 전용으로 비워둔다 — 강조색이 두 가지 일을 겸하지 않게 하려는 것이 3번 문제의 해법이다.

### 폰트
```
--f-ui   : 'IBM Plex Sans KR', 'IBM Plex Sans', -apple-system, 'Malgun Gothic', sans-serif
--f-mono : 'IBM Plex Mono', 'Consolas', monospace
```
- Inter → **IBM Plex Sans KR**. 한글이 포함된 공학 계열 서체라 도면 UI에 맞고, 무엇보다 "어느 앱에서나 보는 그 폰트"가 아니다.
- **숫자는 전부 모노**로 간다. 번호 배지(`1F-01`), 카운터, 배율, 좌표, 라이선스 키 — 실제 도면의 주기(注記)가 그렇듯 자릿수가 흔들리지 않는다.
- **오프라인 주의**: Electron 빌드는 CDN을 못 쓴다. `lib/fonts/` 에 woff2 를 넣고 `@font-face` 로 선언할 것 (현재 Inter 도 CDN `@import` 라 같은 문제를 안고 있다).

### 5-b. 도면 위 렌더 사양 (캔버스 쪽)

UI가 아니라 **도면에 그려지는 것**이라 담당 파일이 다르다.

| 항목 | 사양 | 담당 | 손볼 것 |
|------|------|------|---------|
| 도곽 | **기존 스타일 유지** — 외곽 테두리가 도면 전체를 감싸고(`strokeRect(M, M, W-2M, H-2M)`), 표제란은 그 안쪽 하단. 셀은 `라벨 좌상단 + 값 그 아래` | `titleBlock.js` | **없음.** 지금 구현이 맞다 |
| 범례 | **우측 상단 고정 + 한 줄에 하나씩** — `[색상 선 │ 설명]` 2열 괘선표, 표제행 없음 | `legend.js` | **없음.** 이미 `bx = canvasW - margin - boxW; by = margin` 로 우측 상단에 고정하고 행마다 하나씩 쌓고 있다. 목업 쪽이 틀렸던 것이라 실제 렌더에 맞춰 고쳤다 |
| 작업범위 안내선 | 도곽 테두리 **안쪽**, 표제란 위까지 | `canvas.js` (`renderAnnotations`) | 도곽이 켜졌을 때 테두리와 겹치지 않도록 여백 확인 |

> 목업의 도곽 글씨는 화면에서 읽히도록 실제보다 크게 그렸다(`tbScale` 약 1.7 상당).
> 비율·구조는 실제와 같으니 크기는 도곽 설정의 배율 슬라이더로 맞추면 된다.

## 6. 이식 순서

한 번에 갈아엎지 말고 아래 순서로 나눠 커밋한다. 각 단계마다 앱이 동작하는 상태를 유지한다.

**1단계 — 토큰 교체 (반나절, 위험 낮음)**
`ui-tokens.css` 의 `[A]` 블록을 `css/style.css` 의 `:root` 와 교체한다.
기존 변수명(`--accent`, `--bg-panel`, `--text-primary` …)을 새 토큰으로 **별칭 연결**해 두면 나머지 CSS가 깨지지 않는다.
```css
--accent: var(--sig);  --bg-panel: var(--c-850);  --text-primary: var(--t-0);
--bg-card: var(--c-800);  --border: var(--c-700);  --text-secondary: var(--t-1);
```
이 단계만 해도 화면 인상이 바뀐다. 여기서 한 번 스크린샷으로 확인.

**2단계 — 폰트 (30분)**
`@import` Inter → IBM Plex Sans KR + IBM Plex Mono. 동시에 `lib/fonts/` 로컬 번들 작업.

**3단계 — 칸 도입 (핵심)**
`ui-tokens.css` 의 `[C] [D]` 블록을 `style.css` 에 추가하고, `index.html` 의 `.toolbar-group` / `.ctrl-group` 을 `.bay > .bay-label + .bay-body` 구조로 바꾼다.

> **클래스명은 바꾸지 말 것.** JS가 클래스로 직접 잡고 있는 것을 확인했다:
>
> | 클래스 | 잡는 곳 |
> |--------|---------|
> | `.tool-btn[data-tool]` | `app.js` 562·564·838·839·853·854·868·869·2100 |
> | `.cat-btn` | `app.js` 692·695·708·1957, `sidebar.js` 317 |
> | `.equip-btn[data-key]` | `app.js` 391 |
> | `.mode-seg-btn` | `app.js` 236·454 |
> | `.tab-btn` | `app.js` 1462·1464 |
>
> 따라서 목업의 새 클래스는 **별칭으로 얹는다**. JS 수정 0줄로 끝난다:
> ```css
> .tbtn, .tool-btn { /* [D] 의 .tbtn 규칙 */ }
> .tbtn.active, .tool-btn.active { /* 램프 */ }
> .cat, .cat-btn { /* [D] 의 .cat 규칙 */ }
> ```
> 반대로 `.btn` 은 툴바 전용이라 `.key`(주요) / `.tbtn`(보통) / `.tbtn.danger`(파괴) 중 어디로 갈지
> 버튼마다 사람이 판단해야 한다 — 5장 표의 배치를 따르면 된다.

**4단계 — 레이아웃 재배치**
5장 표대로 DOM 블록을 옮긴다. id 는 그대로.
모드바를 없앨 때 `#mode-bar-hint`(app.js 251에서 안내 문구를 넣는다)는 **삭제하지 말고** 레일의 작업유형 칸 옆으로 옮기거나, 자리가 없으면 `display:none` 인 채로 남겨 둔다.

**5단계 — 도곽 서랍**
`.modal-overlay` 를 `#drawer` 로 교체. 열림/닫힘은 `classList.toggle('open')` 하나로 끝난다.
`#drawer` 의 `top` 은 `calc(var(--rail-h) + var(--bar-h))` 이므로 계기바가 줄바꿈되면 어긋난다 —
계기바를 한 줄로 유지하거나, 여의치 않으면 `top` 을 JS로 실측해 넣는다.

## 7. 검증 방법

목업은 Electron 으로 실제 렌더해서 확인했다. 같은 방법으로 이식 후에도 검증할 수 있다.

```bash
# scripts/shot.js 로 두면 재사용 가능
SHOT_TARGET=<html 절대경로> SHOT_OUT=<png 경로> \
  ./node_modules/.bin/electron --no-sandbox scripts/shot.js
```
숨김 창은 CSS 트랜지션이 스로틀링되므로, 서랍처럼 애니메이션되는 요소를 찍을 때는
캡처 직전에 `*{transition:none !important}` 를 주입할 것.

확인 항목:
- [ ] 1600px 에서 계기바가 **한 줄**로 들어오는가
- [ ] 1400px 이하에서 상단 레일 라벨셀이 접히고 가로 스크롤이 생기지 않는가
- [ ] 도곽 서랍이 닫힌 상태에서 화면 밖으로 **완전히** 나가는가
- [ ] 선택된 도구의 램프가 보이는가 (색 말고 형태로도 구분되는가)
- [ ] 도면 위 잉크 3색이 PDF 출력 색과 같은가

## 9. 남은 판단거리

- **밝은 테마도 필요한가.** 현장 노트북에서 밝은 화면이 나은 상황이 있다면, 크롬 토큰 6개만 뒤집는 라이트 변형을 `[data-theme="light"]` 로 추가하면 된다 — 나머지 CSS는 그대로다. 다만 두 벌을 유지하는 비용이 있으니, 실제로 요청이 있을 때 하는 편이 낫다.
- **장비시험망도 모드**의 장비 버튼(`#equip-btns`)은 개수가 가변이라 칸 하나가 한 줄을 다 쓴다. 현재 `flex:1 1 100%` 방식 그대로 두되, 칸 라벨은 `장비` 로 붙인다.
- **아이콘**. 지금은 stroke 2px 라인 아이콘(범용 세트)이다. 칸이 식별을 담당하므로 급하진 않지만, 나중에 지시선 4종·해치 2종만이라도 실제 도면 기호에 가깝게 다시 그리면 완성도가 올라간다.
